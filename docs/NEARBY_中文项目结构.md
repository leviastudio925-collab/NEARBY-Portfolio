# NEARBY｜熟悉的物品，触手可及

**作品集版本**：6 面，每面 1684 × 595 px。英文内容已排入 Figma；本文是对应的中文文案与项目说明。字体为 IBM Plex Sans，视觉主色为暖橙 `#F28A2E`，辅以瓷白、暖灰和石墨黑。

## 项目定位与证据边界

NEARBY 是面向与痴呆症共同生活的长者及其照护者的**家庭移动收纳柜概念**。它把眼镜、电话、水和纸巾放在可预测的固定位置；长者可以请求柜子靠近，柜子停稳后才取物，必要时可通过 HELP 请求照护者协助。熟悉位置、清楚状态和照护者共同设置，比“自动跟随”本身更重要。

项目只继承原始实体视频中的**箱体、升降台面、小轮、手机遥控和摄像画面**等早期技术尝试。新外观、家庭用途、COME / STAY / HELP 实体控制、家属端界面、住宅地图、路线识别、禁入区、障碍停车与服务流程均为重新设计的**待验证方案**。现有视频未证明这些功能已实现，也未开展痴呆症用户实地研究或临床效果验证。图中的用户画像和日常旅程是研究假设，不是访谈结果。

## 01｜封面与背景

**NEARBY — Familiar things. Within reach.** 画面采用左侧深色编辑栏、中间 Blender 家庭场景、右侧高密度背景信息。中间的同一台产品展示两个明确状态：停靠时升起取物台面；移动时恢复紧凑外形。视觉重心是人、居家环境与装置之间的关系，而不只是孤立的产品渲染。

**要解决的问题**：日常物品放错位置会带来困扰；当物品离使用者较远时，取物又可能需要他人协助。设计机会是让物品的**内部摆放保持固定**，而在获得请求后让载体靠近。初步设计原则：同一物品放同一格；约定固定停靠点；移动和停止有明确提示；协助请求是一条单独流程。页脚列出痴呆症相关资料来源。

## 02｜Field Research：研究问题与假设

这一页沿用参考的左右结构：左侧是三组问题分类，右侧是利益相关方、需求重述与六步日常旅程。副标题必须保留“**二手资料研究 + 拟开展的家庭实地研究**”，避免把后续调研写成已完成。

1. **人—物**：固定物品位置是否有助于识别？移动柜体会不会反而破坏熟悉感？
2. **人—空间**：柜子可以停在何处而不妨碍行走、转身和使用家具？
3. **人—照护者**：谁负责补货、充电、确认帮助请求和处理异常？这项维护是否增加负担？

暂定利益相关方是使用者、家庭照护者和专业照护人员。需求框架为 **Recognize / Reach / Reassure**：认出熟悉位置、在明确请求后取到物品、理解移动和帮助请求的状态。模拟旅程为清晨在固定椅子旁找眼镜 → 换到另一房间 → 请求柜子 → 等待停靠 → 取用并归位 → 必要时发出协助请求与家属检查。每一步都应通过真实家庭观察、共同设计和比较原型来验证。

## 03｜设计概念与造型发展

左侧深色区表达主概念：**保持物品摆放不变，只在使用者希望时改变距离**。四个动作词是 FIND（识别固定物位）、COME（请求靠近）、STAY（先停稳）、HELP（联系可信赖的照护者）。COME、STAY、HELP 既存在于柜体，也存在于简化遥控器；图标与文字双重表达，实际理解度仍需测试。

中间为三张从本次可编辑 Blender 模型导出的正视、侧视和透视形态研究。它们是**本次新制作的数字形态推敲，不是历史手绘草图**。白色圆角柜体、可升降置物台、可封闭低轮底座和小状态显示器延续原视频的基本构型；暖橙只用于交互重点。

右侧以 READY → MOVING → PARKED 为主状态；遇到未知目标、障碍或按下 STAY 时进入 STOPPED，说明原因并等待再次明确请求，不能默认自动恢复。对照方案为静态收纳、手动推车和请求式移动柜体。只有当移动版在熟悉感、可理解性、安全和照护负担方面更好时，才值得继续。

## 04｜系统设计、触点与家庭地图

**左侧系统图**包含长者、柜体、照护者、家庭地图和固定物品。家属与长者共同约定物品、停靠点和照护方式；局部地图与路线属于新的方案。实体 STAY/STOP 始终可用，照护者可以调整停靠点。

**中间触点**展示真实 Blender 新模型以及柜体的升降台面、抽屉、三枚实体按钮、状态提示和家属端界面。拟议流程为家属陪同完成初次建图 → 标记房间与熟悉停靠点 → 审查禁入区及通道 → 收到明确请求后才移动。完整的定位、路径规划、避障和家庭安全能力尚未实现，必须进行工程和居家验证。

**右侧场地模拟**已改为参考所示的轴测拆解画法：上层分离客厅、卧室等生活场景，中层展示开放墙体住宅模型，下层是路线平面图。A 为日常座椅停靠点，B 为床边停靠点；橙色虚线为**拟议路线**，浴室以暖橙区表示家属设定的禁入区。轴测图在 Figma 中为可缩放的矢量图层；家属端界面另外保留简化的平面地图和障碍停车示例。它们都是视觉化设计推演，不是传感器实际扫描数据，也不代表现有设备可以自主识图或导航。技术依据采用 ROS/Nav2 的建图和 keepout-zone 官方文档，只作为设计机制参考。

## 05｜User Flow 与高保真界面

**长者流程**：共同确定需求 → 家属陪同查看家庭地图与熟悉停靠点 → 通过 COME 请求靠近 → 柜子显示移动状态、STAY 随时可用 → 停稳后取用物品。**HELP 流程**单独显示“发送中 / 已送达 / 未送达 / 家属已确认”，避免把发出请求等同于获得照护。

**家属端高保真界面**展示首页、固定物品清单、家庭地图审查、帮助请求。地图界面是新增加的一屏，房间和禁入区均为可编辑图层，并通过“查看家庭地图 → 确认并启用”接入 Figma 原型。图上的 A/B 点位、路线和障碍代表模拟例子。家属端还包括配对、暂停、目标丢失和请求失败等恢复状态。个人端遥控器保留大字、直接动作和明确反馈。所有操作仍为 Figma 交互原型，不连接真实硬件或通知服务。

## 06｜原型依据、服务与验证

左侧三张真实视频截图记录旧 demo 的手机遥控、升降台面、箱体与安装手机。中间以使用者、家属、柜体和服务四条泳道描述“协商—设置—使用—维护”，提醒作品不止是产品外壳。右侧是验证计划而非成果：先与长者、家属和专业人士共同设计；把静态收纳、手推车和请求移动柜体放在相同任务中比较；观察找物、归位、提示理解、障碍停车、维护和接受/拒绝。若移动造成困惑或额外工作，应缩减自动化或返回静态方案。
